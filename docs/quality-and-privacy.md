# SAYNUE 개인정보 최소화형 피드백 / 품질 검증 메모
2026-11-17 · 실서비스 MVP, 정식 법률 문서 아님

## 평가 피드백
- 사용자가 분석 리포트를 본 뒤 **도움됐어요 / 아쉬웠어요** 중 하나를 직접 누르는 방식.
- 전송하는 데이터의 전체 범위: `rating`(2개 허용값), `goal`(4개 허용값), `locale`(5개 허용값). 채팅 내용, 답장 문장, 점수, 파일, 전화번호, 사용자 ID는 **수집하지 않음**.
- 서버는 미허용 필드나 자유입력 필드를 400으로 거절. 512바이트 본문 상한, 같은 출처 제한, 인스턴스당 IP 해시 기반 시간당 5회 제한(분산 공격 방어 보장은 아님).
- 현재 Vercel에는 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`이 없으므로 **서버 단기 실행 로그**에만 범주형 평가를 기록한다. Hobby 로그 보존 기간에 따른 제한이 있으며 영구 저장/통계를 주장할 수 없다.
- Upstash Redis REST 변수를 **사용자가 Vercel Settings에서 직접 구성**하면, 일별 `saynue:feedback:YYYY-MM-DD:rating:goal:locale` 횟수 합산 카운터를 Redis에 기록하고 90,000초(25시간) 뒤 만료. 즉, 이 방식 역시 단기간의 경향 집계이며 장기 보존을 의도하지 않는다.
- 피드백 실패는 성공으로 표시하지 않고 재시도 안내한다. 자동 화면 조회 추적, 사용자 세션 추적, 광고용 추적 도구는 설치하지 않는다.

## 품질 검증
- `tests/quality-cases.mjs`에 **30개의 가상·합성 예시**를 포함: 한국어, 일본어, 영어, 중국어 간체/번체 각 6개.
- 관계: 썸, 연인, 전 연인, 친구, 직장, 짝사랑. 과제: 애매함, 명시적 거절, 사과·화해, 시간·연락 경계, 비연애적 업무, 기분 배려.
- `tests/quality.test.mjs`의 30개 시나리오는 API 입력→모델 요청→허용된 결과 필드 전달 경로를 **모의 모델 응답으로 검증**한다. 모델의 실제 판단 품질을 입증하지 않는다.
- `tests/feedback.test.mjs`는 민감한 자유입력 거절, 응답의 no-store, 로그에 허용값 외 정보 미포함, 간이 횟수 제한, Redis 일별 카운터를 점검한다.
- 실제 AI 품질 평가는 별도 합성 사례의 Gemini 실호출을 통해 확인하되, 문장 자연스러움·근거 정확성·문화적 맥락·경계 존중·잘못된 확신 여부를 수동 검토해야 한다.

## 품질 평가 척도 (테스터 가이드)
각 항목 1~5점. 5점이 양호.
1. **구체성**: 입력 대화의 실제 신호를 짚었는가?
2. **신중함**: 타인의 속마음과 감정을 단정하지 않았는가?
3. **행동 가능성**: 다음 행동·답장 문장이 실제로 적합한가?
4. **자연스러움**: 해당 언어와 관계의 말투에 자연스러운가?
5. **경계 존중**: 거절·동의·휴식·업무 경계를 존중하는가?

대화 원문 저장 없이 각 항목 점수만 합산한다. **평균 점수와 합격률은 아직 실제 사용자 데이터로 검증되지 않았다.**

## 베타 공개 전 반드시 남은 일
- 개인정보처리방침과 이용약관에 사업자/운영자 연락처, 처리자, 법적 근거, 데이터 보관·삭제, 국가별 고지 등을 넣어 최종 검토. 현재 운영자 정보가 없으므로 정식 문서를 임의 작성하지 않는다.
- Gemini API 무료/유료의 데이터 처리 조건과 분석하는 타인 대화의 개인정보 및 동의 문제 검토.
- Upstash 구성, 분산 속도 제한, 일일 AI 예산, 봇 방어, 모니터링.
- 5개 언어·스크린샷 실기기 테스트. 합성 테스트가 실제 대화·이미지의 안정성을 보장하지는 않는다.
- 결제는 서버 측 구매검증·환불·법정 표시 완료 전 비활성화 유지.
